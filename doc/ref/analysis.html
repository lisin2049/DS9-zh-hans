Analysis 分析

Each file type known to DS9 can have user-defined analysis commands associated with it. These analysis commands are defined at start-up time , or loaded by the user, by means of an ASCII analysis description file. The analysis commands are available for execution, either via the Analysis Menu or the XPA point Analysis. In addition, commands may be bound to events, such as keystrokes or mouse clicks. This type of command is called a bind command.

DS9 已知的每种文件类型都可以关联用户自定义的分析（analysis）命令。这些分析命令在启动时定义，或由用户通过一个 ASCII 分析描述文件加载。分析命令既可通过 Analysis Menu（分析菜单）执行，也可通过 XPA 点 Analysis 执行。此外，命令还可以 绑定（bind）到事件上，如按键或鼠标点击；这种命令称为绑定命令（bind command）。

DS9 searches for an analysis file named ds9.ans or ds9.analysis in the current directory and $HOME to be loaded at startup. In addition, DS9 will search the following directories for any analysis files to be loaded at startup in the form of *.ds9: the current directory, $HOME/bin, /usr/local/bin, /opt/local/bin, and /soft/saord/bin. Finally, the user may specify analysis files to be loaded at startup in the preferences analysis panel. The user may also load or clear current analysis commands via command line options or the Analysis menu.

DS9 会在当前目录和 $HOME 中查找名为 ds9.ans 或 ds9.analysis 的分析文件，于启动时加载。此外，DS9 还会在以下目录中查找以 *.ds9 形式存在、于启动时加载的分析文件：当前目录、$HOME/bin、/usr/local/bin、/opt/local/bin 和 /soft/saord/bin。最后，用户可在首选项的分析面板中指定启动时加载的分析文件，也可通过命令行选项或 Analysis 菜单 加载或清除当前的分析命令。

When activated, either from the menu, XPA, or bound event, an analysis command first is macro-expanded to fill in user-defined arguments and then is executed externally. Results may be displayed in a separate text window, plot window, or in a image frame.

当分析命令被激活（无论来自菜单、XPA 还是绑定事件）时，首先进行宏展开以填入用户定义的参数，然后在外部执行。结果可显示在单独的文本窗口、绘图窗口或某个图像帧中。

Analysis -> Make Catalog is a built-in command that measures all supported regions in the current image frame and opens a live Catalog Tool. It is not defined by an analysis command file. See Region Statistics Catalog for details.

Analysis -> Make Catalog 是一个内置命令，用于测量当前图像帧中所有受支持的区域并打开实时星表工具。它不由分析命令文件定义。详见 区域统计星表。

Syntax

语法

The analysis file that defines the known analysis commands consists of one or more file descriptors, each of which has the following format:

定义已知分析命令的分析文件由一个或多个文件描述符组成，每个描述符具有如下格式：

Menu label to be used
A space separated list of file templates
Command type [menu | bind <event> | button]
The command line for the analysis program

（上方四行依次为：所用菜单标签、以空格分隔的文件模板列表、命令类型 [menu | bind <事件> | button]、分析程序的命令行。命令块保持原样。）

Task names may contain space characters. All lines may be indented. Also, the '#' character is a comment character. A separator can be inserted in the menu by specifying the following sequence '---'.

任务名可以包含空格字符。所有行都可缩进。此外，'#' 是注释字符。通过指定 '---' 序列可在菜单中插入分隔线。

Example:

示例：

# this will insert a menu separator
---

（上面为插入菜单分隔线的示例，保持原样。）

A bind command is a command that is bound to an event. When the event occurs, the command is executed. Types of events available include all TK events, including all keystrokes and mouse clicks. Parameters

参数

The user may define his own macros or parameters to be evaluated before the command line is executed. To do this, the user defines a parameter segment that is referenced in the command line. Parameters may be displayed in a notebook style via use of the 'tab' 'endtab' keywords. The parameter definition has the following format:

用户可以定义自己的宏或参数，在命令行执行前求值。为此，用户定义一个参数段，并在命令行中引用它。参数可通过 'tab' 'endtab' 关键字以笔记本（分页）样式显示。参数定义格式如下：

param <name>
  <variable> <entry|text|checkbox|menu|combobox|open|save> <title> <default> <{comment}>
  ...
endparam

（上方为参数定义的基本格式：param 名、变量及控件类型/标题/默认值/注释、endparam 结束，保持原样。）

param <name>
tab <text>
  <variable> <entry|text|checkbox|menu|comboxbox|open|save> <title> <default> <{comment}>
  ...
endtab
tab <text>
  <variable> <entry|text|checkbox|menu|combobox|open|save> <title> <default> <{comment}>
 ...
endtab
endparam

（上方为带 tab 分页的参数定义格式，保持原样。）

or

或者：

param <name>
@<iraf param filename>
end

（上方为引用 IRAF 参数文件的参数定义格式，保持原样。）

The definition either consists of a number of variables, one per row, or the name of an IRAF style parameter file. DS9 will look for the IRAF parameter file in:

定义要么由若干变量组成（每行一个），要么是一个 IRAF 风格参数文件的文件名。DS9 会在以下位置查找该 IRAF 参数文件：

./<filename>
$UPARM/<filename>
$HOME/iraf/<filename>

（上方为查找位置列表，保持原样。）

The following macros are supported if encountered in the default field:

若默认字段中出现以下宏，则会被支持：

$width
$height
$depth
$bitpix
$filename
$filename[region]
$env

（上方为默认字段中支持的宏列表，保持原样。）

Hierarchical Menus

分层菜单

The user may define hierarchical menus. Use this to organize crowded menus. To do this, frame menu entries with hmenu <label> and endhmenu. Hierarchical menu labels may contain spaces. Multiple levels may be implemented.

用户可以定义分层菜单（hierarchical menus），用以组织拥挤的菜单。做法是用 hmenu <标签> 和 endhmenu 把菜单项括起来。分层菜单标签可以包含空格，可实现多层。

Example:

示例：

hmenu Stuff
  hello
  *
  menu
  echo "Hello" | $text

  world
  *
  menu
  echo "World" | $text

  hmenu More Stuff
    hello world
    *
    menu
    echo "Hello World" | $text
  endhmenu
endhmenu

（上面为分层菜单示例：Stuff 下含 hello、world 及嵌套的 More Stuff，保持原样。）

Will create an hierarchical menu with two members, hello and world.

将创建一个含两个成员 hello 和 world 的分层菜单。
