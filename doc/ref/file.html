FITS

FITS

DS9 supports FITS images and FITS binary tables. The following algorithm is used to locate and to load the FITS image or table if no additional information is provide:

DS9 支持 FITS 图像和 FITS 二进制表。如果未提供附加信息，DS9 按以下算法查找并加载 FITS 图像或表：

  • Examine primary HDU, if IMAGE, load.

    检查主 HDU：若是 IMAGE（图像），则加载。

  • Examine each extension HDU

    逐一检查每个扩展 HDU。

    • If IMAGE, load.

      若是 IMAGE，则加载。

    • If BINARY TABLE, create IMAGE if the following is true:

      若是 BINARY TABLE（二进制表），且满足以下任一条件，则将其生成图像：

      • FITS COMPRESSED: keyword ZIMAGE is T.

        压缩 FITS：关键字 ZIMAGE 为 T。

      • FITS EVENTS: keyword EXTNAME is EVENTS,STDEVT, or RAYEVENT, column names X and Y are present.

        FITS 事件表：关键字 EXTNAME 为 EVENTS、STDEVT 或 RAYEVENT，且存在名为 X 和 Y 的列。

      • FITS HEALPIX: keyword PIXTYPE is HEALPIX.

        FITS HEALPIX：关键字 PIXTYPE 为 HEALPIX。

  • If DS9 traverses the entire FITS file without satisfying one of the above, an error is generated.

    如果 DS9 遍历了整个 FITS 文件仍不满足上述任一条件，则产生错误。

FITS keyword inheritance is supported. All valid FITS BITPIX values are supported, along with -16, for UNSIGNED SHORT. The following FITS keywords are supported:

DS9 支持 FITS 关键字继承。所有合法的 FITS BITPIX 取值都受支持，另外还支持用于 UNSIGNED SHORT（无符号短整型）的 -16。受支持的 FITS 关键字如下：

OBJECT
UNITS
BSCALE / BZERO
BLANK
DATASEC
LTV / LTM  for physical coords
DTV / DTM  for detector coords
ATV / ATM  for amplifier coords
WCS keywords
WCS# keywords

上表列出的受支持关键字包括：OBJECT（目标）、UNITS（单位）、BSCALE/BZERO（缩放/零点）、BLANK（空像素值）、DATASEC、用于物理坐标的 LTV/LTM、用于探测器坐标的 DTV/DTM、用于放大器坐标的 ATV/ATM，以及 WCS 关键字和 WCS# 多坐标系关键字。

FITS Image

FITS 图像

At load time, the user may provide just a file name or a file name along with FITS extension name/number and image section specification. FITS extension names are case insensitive. When specifying an extension, be sure to quote strings correctly to pass both the shell and DS9 parser. A image section specification is used to specify the x,y limits of an image subsection. By default, x and y coordinates are in IMAGE, use a 'p' as the last character to indicate PHYSICAL coordinates. A '*' indicates use the default for that axis only. Block is optional and defaults to 1.

加载时，用户可以只给出文件名，也可以连同 FITS 扩展名/扩展序号以及图像段（image section）说明一起给出。FITS 扩展名不区分大小写。指定扩展时，请注意正确地给字符串加引号，使其能同时通过 shell 和 DS9 解析器。图像段说明用于指定图像子区域的 x、y 范围。默认情况下 x、y 坐标为 IMAGE（图像）坐标；在末尾加一个 'p' 表示 PHYSICAL（物理）坐标。'*' 表示该轴取默认范围。Block（分箱因子）为可选项，默认为 1。

Syntax:
filename
filename[ext]
filename[ext][sect]
filename[sect]
filename[ext,sect]

where

ext:
[extension name | extension #]

sect:
[x0:x1,y0:y1[p]]
[x0:x1,y0:y1,block[p]]
[x0:x1,y0:y1,z0:z1[p]]
[x0:x1,y0:y1,block,z0:z1[p]]
[*,y0:y1[p]]
[*,y0:y1,block[p]]
[*,y0:y1,z0:z1[p]]
[*,y0:y1,block,z0:z1[p]]
[x0:x1,*[p]]
[x0:x1,*,block[p]]
[x0:x1,*,z0:z1[p]]
[x0:x1,*,block,z0:z1[p]]
[*,*,block]
[*,*,z0:z1]
[*,*,block,z0:z1]

[dim1@xcen,dim2@ycen[p]]
[dim1@xcen,dim2@ycen,block[p]]
[dim1@xcen,dim2@ycen,dim3@zcen[p]]
[dim1@xcen,dim2@ycen,block,dim3@zcen[p]]
[*,dim2@ycen[p]]
[*,dim2@ycen,block[p]]
[*,dim2@ycen,dim3@zcen[p]]
[*,dim2@ycen,block,dim3@zcen[p]]
[dim1@xcen,*[p]]
[dim1@xcen,*,block[p]]
[dim1@xcen,*,dim3@zcen[p]]
[dim1@xcen,*,block,dim3@zcen[p]]
[*,*,block]
[*,*,dim3@zcen]
[*,*,block,dim3@zcen]

[dim@xcen@ycen]
[dim@xcen@ycen,block]
[dim@xcen@ycen,zdim@zcen]
[dim@xcen@ycen,block,zdim@zcen]

Example:
$ds9 foo.fits # default load
$ds9 foo.fits[1] # load first extension
$ds9 foo.fits[BCKGRD] # load extension named 'BCKGRD'
$ds9 foo.fits[10:200,40:100] # image section
$ds9 foo.fits[10:200,40:100,2] # image section, blocked by 2
$ds9 foo.fits[*,40:100] # only section y axis
$ds9 foo.fits[256@512@512] # section box at 512,512
$ds9 foo.fits[2][100:200,100:200] # second extension, image section
$ds9 foo.fits[2][100:200,100:200,2] # second extension, image section, blocked by 2
$ds9 foo.fits[10:200,40:100,5:20] # cube section
$ds9 foo.fits[*,40:100,5:20] # only section y and z axes
$ds9 foo.fits[256@512@512] # section cube at 512,512
$ds9 foo.fits[2][100:200,100:200,5:20] # second extension, cube section
$ds9 foo.fits[2][100:200,100:200,2,5:20] # second extension, cube section, blocked by 2

以上为 FITS 文件名语法：ext 为扩展名或扩展序号；sect 为图像段，用 [x0:x1,y0:y1] 指定范围，末尾加 p 表示物理坐标，可用 block 因子分箱，三维时可加 z0:z1；也可用 dim@xcen 的形式指定以某点为中心的子区域。注释行（# 后）给出了各示例的含义，如默认加载、按序号/名称加载扩展、裁剪区域、2 倍分箱、立方体段等。

FITS Binary Events Table

 At load time, the user may provide just a file name or a file name along with FITS extension name/number, image section specification, and binnng parameters. DS9 will automatically convert an FITS binary events table into a 2D image for display. FITS extension names and parameters are case insensitive. The users may specify a number of parameters on how to construct the image and how to filter data. When specifying a filter, be sure to quote strings correctly to pass both the shell and DS9 parser.

FITS 二进制事件表。加载时，用户可以只给出文件名，也可以连同 FITS 扩展名/序号、图像段说明以及分箱（binning）参数一起给出。DS9 会自动把 FITS 二进制事件表转换为二维图像用于显示。FITS 扩展名和参数不区分大小写。用户可以指定若干参数来控制如何构建图像以及如何筛选数据。指定筛选条件时，请注意正确给字符串加引号，使其能同时通过 shell 和 DS9 解析器。

Syntax:
filename
filename[ext]
filename[ext][sect]
filename[sect]
filename[ext,sect]

filename[ext][bin]
filename[ext][bin][sect]
filename[ext][sect][bin]
filename[bin]
filename[bin][sect]
filename[sect][bin]
filename[ext,bin]

where:
ext: see FITS Image
sect: see FITS Image

bin:
[bin=colx,coly] # bin counts
[bin=colx,coly,filter] # bin counts with filter
[bin=colx,coly,colz] # bin on colz
[bin=colx,coly,colz,filter] # bin on colz with filter
[bin=colz] # bin cols 'x', 'y', and colz
[bin=colz,filter] # bin cols 'x', 'y', and colz with filter
[key=colx,coly]
[binkey=colx,coly]

(see Introduction to Filtering)

Example:
$ds9 foo.fits # default load
$ds9 foo.fits[1] # load first extension
$ds9 foo.fits[BCKGRD] # load extension named 'BCKGRD'
$ds9 foo.fits[bin=detx,dety] # bin on detx,dety
$ds9 foo.fits[2][bin=rawx,rawy] # load ext 2, cols rawx,rawy
$ds9 foo.fits[bg_events,bin=rawx,rawy] # load ext bg_events, cols rawx,rawy
$ds9 foo.fits[bin=x,y,pha] # bin on x,y,pi
$ds9 foo.fits[bin=pi] # bin on x,y,pi
$ds9 'foo.fits[ccd_id==3&&energy>4000]' # quoted filter
$ds9 '"foo.fits[ccd_id==3 && energy>4000]"' # double quoted filter
$ds9 'foo.fits[events][pha>5,pi<2]' # load extension 'events' and filter

以上为事件表语法：ext、sect 同前；bin 子句用 [bin=colx,coly] 指定分箱所用的两列，可再加第三列（如 pha/pi）或 filter 筛选表达式；注释行给出了各示例含义。筛选表达式的语法另见 Funtools 的《Introduction to Filtering》；带 &&、>、< 的筛选条件需要按示例那样用引号包起来。

The shell environment variable DS9_BINKEY may be used to specify default bin cols for FITS bin tables. Example:

可以使用 shell 环境变量 DS9_BINKEY 为 FITS 分箱表指定默认的分箱列。示例：

$ export DS9_BINKEY='[bin=rawx,rawy]'
$ ds9 foo.fits # load FITS bin table, bin on rawx, rawy

先用 export 设置 DS9_BINKEY 默认分箱列为 rawx、rawy，之后直接加载 FITS 分箱表时就会按该默认分箱。

FITS HEALPIX Table

FITS HEALPIX 表

At load time, the user may provide just a file name or a file name along with FITS extension name/number, image section specification, and Healpix parameters. DS9 will automatically convert a FITS HEALPIX binary or ascii table into a 2D image for display. FITS extension names and parameters are case insensitive. The users may specify a number of parameters on how to construct the image. Any table with keyword PIXTYPE=HEALPIX or NSIDE=x will be processed as an HEALPIX image. Space MOC/partial HEALPIX binary tables using ORDERING=NUNIQ and a UNIQ or NPIX index column will also be displayed as HEALPIX images. The following FITS keywords will be used if present and not overwritten by a command line option: NSIDE, COORDSYS, ORDER, MOCORD_S, MOCORDER, HPXMOC.

加载时，用户可以只给出文件名，也可以连同 FITS 扩展名/序号、图像段说明以及 Healpix 参数一起给出。DS9 会自动把 FITS HEALPIX 二进制表或 ASCII 表转换为二维图像用于显示。FITS 扩展名和参数不区分大小写，用户可以指定若干参数来控制如何构建图像。任何带关键字 PIXTYPE=HEALPIX 或 NSIDE=x 的表都会被当作 HEALPIX 图像处理；使用 ORDERING=NUNIQ 且带 UNIQ 或 NPIX 索引列的空间 MOC/部分 HEALPIX 二进制表也会作为 HEALPIX 图像显示。若存在且未被命令行选项覆盖，将使用以下 FITS 关键字：NSIDE、COORDSYS、ORDER、MOCORD_S、MOCORDER、HPXMOC。

Syntax:
filename
filename[ext]
filename[ext][sect]
filename[sect]
filename[ext,sect]

filename[ext][hpx]
filename[ext][hpx][sect]
filename[ext][sect][hpx]
filename[hpx]
filename[hpx][sect]
filename[sect][hpx]
filename[ext,hpx]

where:
ext: see FITS Image
sect: see FITS Image

hpx:
[order=ring|nested] # default ring
[layout=equatorial|north|south] # default equatorial
[col=<column number>] # defaut 1
[quad=<quadurant number>] # (1-4) default 1
[system=equatorial|galactic|ecliptic|unknown] # default unknown

Example:
$ds9 foo.fits # default load
$ds9 foo.fits[1] # load first extension
$ds9 foo.fits[order=ring,layout=equatorial,col=1,quad=1,system=unknown]
$ds9 foo.fits[1,order=nested] # first extension, nested order

以上为 HEALPIX 表语法：ext、sect 同前；hpx 子句中 order 指定 HEALPIX 排列方式（ring 环序，默认；nested 嵌套序），layout 指定布局（赤道/北天/南天），col 指定数据列号（默认 1），quad 指定象限（1–4，默认 1），system 指定坐标系（赤道/银道/黄道/未知，默认未知）。

FITS Cube

FITS 立方体

A FITS Cube is a FITS image which contains more than 2 axes (NAXES>2). DS9 will automatically detect if a cube is present and will load all additional images. In addition, individual images can be loaded one at a time into a cube. DS9 will display the Cube dialog box which allows the user to select which 2 image to be displayed.

FITS 立方体是指包含超过 2 个轴（NAXES>2）的 FITS 图像。DS9 会自动检测是否存在立方体并加载所有附加的图像；此外，也可以逐张把单个图像加载进一个立方体。DS9 会弹出 Cube 对话框，让用户选择要显示哪一二维图像。

FITS Multiple Extension Cube

FITS 多扩展立方体

A FITS Multiple Extension Data Cube file is a FITS file with one or more extensions, that is to be displayed as a data cube. Each image does not have to be the same size, however, only the coordinate systems from the first extension will be used for contours and grids.

FITS 多扩展数据立方体文件是指一个带有一个或多个扩展、需要作为数据立方体显示的 FITS 文件。各图像尺寸不必相同，但等高线和网格只会使用第一个扩展的坐标系。

Example:
$ds9 -mecube foo.fits # load multiple extension fits file as data cube

示例：用 -mecube 选项把多扩展 FITS 文件作为数据立方体加载。

FITS Multiple Extension Multiple Frames

FITS 多扩展多帧

Load a multiple extension FITS file into multiple frames. Please note that files loaded via standard-in or the xpa fits command can not be displayed using this method.

把多扩展 FITS 文件加载到多个帧中。请注意：通过标准输入（stdin）或 xpa fits 命令加载的文件不能用此方式显示。

Example:
$ds9 -multiframe foo.fits # load multiple extension fits file as multiple frames

示例：用 -multiframe 选项把多扩展 FITS 文件加载为多个帧。

FITS Mosaic

FITS 拼接

A FITS mosaic image may exist as a series of FITS files, or as one FITS file with many extensions. A FITS mosaic may be loaded all a one time, or by the segment. Once loaded, the multiple FITS images are treated as one FITS image.

FITS 拼接图像（mosaic）可以是一系列 FITS 文件，也可以是一个带多个扩展的 FITS 文件。拼接图像可以一次性整体加载，也可以按分段（segment）加载。加载后，多个 FITS 图像被当作一个 FITS 图像处理。


DS9 supports three forms of mosaics: 

DS9 支持三种形式的拼接：

IRAF
 contains the DETSEC and DETSIZE keywords.
See NOAO IRAF Mosaic Data Structures
WCS
 each FITS image contains a valid WCS.
HST WFPC2
 valid HST WFPC2 data cube, consisting of 4 planes, along with a fits ascii table containing wcs information.

上表：IRAF 拼接——包含 DETSEC 和 DETSIZE 关键字（详见 NOAO IRAF 拼接数据结构文档）；WCS 拼接——每个 FITS 图像都包含一个有效的 WCS；HST WFPC2——有效的 HST WFPC2 数据立方体，由 4 个平面组成，并附带一个包含 WCS 信息的 FITS ASCII 表。

Example:
$ds9 -mosaicimage iraf foo.fits # load mosaic iraf from one fits file with multiple exts
$ds9 -mosaic iraf foo.fits bar.fits wow.fits # load mosaic iraf from 3 files
$ds9 -mosaicimage wcs foo.fits # load mosaic wcs from one fits file with multiple exts
$ds9 -mosaic wcs foo.fits bar.fits wow.fits # load mosaic wcs from 3 files
$ds9 -mosaicimage wfpc2 bar.fits # load wfpc2 mosaic
$ds9 -mosaic foo.fits bar.fits wow.fits # load mosaic (wcs) from 3 files

示例：-mosaicimage iraf/wcs/wfpc2 用于从单个多扩展 FITS 文件加载拼接；-mosaic 用于从多个文件加载拼接（默认按 WCS 拼接）。

FITS Mosaic Data Cube

FITS 拼接数据立方体

A FITS Mosaic Data Cube is a FITS mosaic image which contains more than 2 axes (NAXES>2). DS9 will automatically detect if a mosaic data cube is present and will load all additional images. At the same time, DS9 will display the data cube dialog box which allows the user to select which 2 image to be displayed.

FITS 拼接数据立方体是指包含超过 2 个轴（NAXES>2）的 FITS 拼接图像。DS9 会自动检测是否存在拼接数据立方体并加载所有附加图像，同时弹出数据立方体对话框，让用户选择要显示哪一二维图像。

FITS RGB

FITS RGB

A FITS RGB image may exist as three of FITS images, one FITS file with three extensions, or as a FITS 3D Data cube, with three slices, each representing the red, green, and blue channel. A FITS RGB image may be loaded all a one time, or by the channel. Once loaded, the multiple FITS images are treated as one FITS image.

FITS RGB 图像可以是三个独立的 FITS 图像、一个带三个扩展的 FITS 文件，或一个带有三个切片的 FITS 三维数据立方体——每个切片分别代表红、绿、蓝通道。RGB 图像可以一次性整体加载，也可以按通道加载。加载后，多个 FITS 图像被当作一个 FITS 图像处理。

Example:
$ds9 -rgbimage rgb.fits # load rgb image consisting of one fits file with 3 image exts
$ds9 -rgbcube cube.fits # load rgb image consisting of one fits data cube
$ds9 -rgb -red foo.fits -green bar.fits -blue wow.fits # rgb image from 3 fits images

示例：-rgbimage 加载含 3 个图像扩展的 RGB FITS 文件；-rgbcube 从一个 FITS 数据立方体加载 RGB；-rgb -red/-green/-blue 分别从三个 FITS 文件构成 RGB 图像。

Split FITS

拆分 FITS

A split fits is a valid fits file in which two files contain the header and data segments.

拆分 FITS（split fits）是一种合法的 FITS 文件：其文件头（header）段和数据（data）段分别存放在两个文件中。

Array

数组（Array）

Raw data arrays are supported. To load an array, the user must provide the dimensions, pixel depth, and optional header size and architecture type.

DS9 支持原始数据数组。加载数组时，用户必须给出维数、像素位深，并可选择给出文件头大小和字节序（架构类型）。

Syntax:
filename[arr]
filename[arr][sect]
filename[sect][arr]
 
where
sect: see FITS Image
arr:
xdim=value
ydim=value
zdim=value # default is a depth of 1
dim=value
dims=value
bitpix=[8|16|-16|32|64|-32|-64]
skip=value # must be even, most must be factor of 4
arch|endian=[big|bigendian|little|littleendian]

arr 子句参数：xdim/ydim/zdim 给出各维大小（zdim 默认为 1）；dim/dims 给出统一维数；bitpix 指定像素类型（8/16/-16/32/64/-32/-64）；skip 为跳过的头字节数（必须为偶数，且最好是 4 的倍数）；arch 或 endian 指定字节序（big 大端 / little 小端）。

Example:
$ds9 -array bar.arr[xdim=512,ydim=512,zdim=1,bitpix=16] # load 512x512 short
$ds9 -array bar.arr[dim=256,bitpix=-32,skip=4] # load 256x256 float with 4 byte head
$ds9 -array bar.arr[dim=512,bitpix=32,arch=little] # load 512x512 long, intel

示例：加载 512×512 短整型数组、带 4 字节头的 256×256 浮点数组、以及小端（intel）512×512 长整型数组。

or alternate format:

或者使用另一种格式：

filename[array(<type><dim><:skip><endian>)]

where:
type:
'b' 8 -bit unsigned char
's' 16-bit short int
'u' 16-bit unsigned short int
'i' 32-bit int
'l' 64-bit int
'r' 32-bit float
'f' 32-bit float
'd' 64-bit float

type 为数组类型代码：b=8 位无符号字符，s=16 位短整型，u=16 位无符号短整型，i=32 位整型，l=64 位整型，r/f=32 位浮点，d=64 位浮点。

dim:
int     # x,y dim
int.int # x,y dim
int.int.int # x,y,z dim

dim 为维数：单个整数表示 x、y 两维；int.int 表示 x、y 维；int.int.int 表示 x、y、z 三维。

skip:
int     # number of bytes to skip

skip 为需要跳过的字节数（即文件头长度）。

endian:
'l' little endian
'b' big endian

endian 指定字节序：l 为小端，b 为大端。

Example:
$ds9 -array bar.arr[array(s512)]   # load 512x512 short
$ds9 -array bar.arr[array(r256:4)] # load 256x256 float with 4 byte head
$ds9 -array bar.arr[array(i512l)]  # load 512x512 long, intel

简洁格式示例：array(s512) 加载 512×512 短整型；array(r256:4) 加载带 4 字节头的 256×256 浮点；array(i512l) 加载小端（intel）512×512 长整型。

The shell environment variable DS9_ARRAY may be used to specify default array parameters.

可以使用 shell 环境变量 DS9_ARRAY 来指定默认的数组参数。

Example:
$export DS9_ARRAY='[dim=256,bitpix=-32]'
$ds9 -array foo.arr # load 256x256 float

示例：export DS9_ARRAY 设置默认参数为 dim=256、bitpix=-32，之后直接加载数组文件即按该默认参数解释。

NRRD (Nearly Raw Raster Data)

NRRD（近原始栅格数据）

Images in NRRD are supported directly. Encodings supported: raw, gzip

DS9 直接支持 NRRD 格式图像。支持的编码方式：raw、gzip。

Syntax:
filename
filename[sect]

where:
sect: see FITS Image

Example:
$ds9 -nrrd foo.nrrd
$ds9 -nrrd foo.nrrd[100:200,100:200] # cropped

External File Support

外部格式支持

DS9 supports external file formats via an ASCII description file. When loading a file into DS9, these descriptions are referenced for instructions for loading the file, based on the file extension. If found, the command is executed and the result, a FITS image or FITS Binary Table, is read into DS9 via stdin.

DS9 通过一个 ASCII 描述文件来支持外部文件格式。把文件加载进 DS9 时，会根据文件扩展名查找这些描述，以获得加载该文件的指令。如果找到匹配项，就执行对应的命令，并把结果（一个 FITS 图像或 FITS 二进制表）通过标准输入读入 DS9。

At start-up, DS9 first searches for the ASCII file, named .ds9.filin the local directory, then in the users home directory.

启动时，DS9 先在当前目录查找名为 .ds9.fil 的 ASCII 文件，然后在用户主目录中查找。

The file command first is macro-expanded to fill in user-defined arguments and then is executed externally.

文件中的命令先进行宏展开以填入用户定义的参数，然后在外部执行。

The ASCII file that defines the known image files consists of one or more file descriptors, each of which has the following format:

定义已知图像文件的 ASCII 文件由一个或多个文件描述项组成，每个描述项格式如下：

Help description
A space-separated list of templates
A space-separated list of file types (not currently used)
The command line for the loading this file type

依次为：帮助说明文本、以空格分隔的文件模板列表、以空格分隔的文件类型列表（当前未使用）、以及加载该类文件时使用的命令行。

Note that blank lines separate the file descriptions and should not be used as part of a description. Also, the '#' character is a comment character.

注意：空行用于分隔各个文件描述项，本身不应作为描述的一部分；另外，'#' 字符为注释字符。

The following macros are supported: $filename

Startup File

If a startup file $HOME/ds9.ini is available, it is sourced as the last step in initialization. The file permissions must be group/world read-only.

Movie Script

影片脚本

The movie script format is used to specify a set of ds9 commands to run to create a movie. The user can run any of the command line options. A frame is added to the movie after each command. For example the script

影片脚本（movie script）格式用于指定一组要依次执行的 ds9 命令，从而生成一段影片。用户可以使用任何命令行选项；每条命令执行后，影片中都会添加一个新帧。例如以下脚本：

pan to 4096 4096 physical
zoom to 1
zoom to 2
zoom to 3
sleep 2
zoom to 2
zoom to 1
pan to 5120 5120 physical

上述脚本：先平移（pan）到物理坐标 4096,4096，再依次放大到 1、2、3 倍，暂停 2 秒，然后缩回 2 倍、1 倍，最后平移到 5120,5120。

will create a movie with 8 frames. The first will be after the current image is panned to the specified location, then the imager will zoom into that location, pause, and zoom out, and then pan to a different location.

该脚本会生成一段含 8 帧的影片：第一帧是当前图像平移到指定位置之后；接着图像逐级放大到该位置、暂停、再缩回，最后平移到另一个位置。

Lines in the script starting with # are treated as comments and ignored. Lines ending with \ are continued onto the next line; multiple continue lines are allowed. Lines ending with && are executed but a new shot/frame is not added to the movie; this allows multiple commands to be run before the next frame is added.

脚本中以 # 开头的行被视为注释并忽略；以 \ 结尾的行续接到下一行（允许多行续接）；以 && 结尾的命令会被执行，但不会向影片添加新的镜头/帧——这样就可以在添加下一帧之前连续执行多条命令。

The sleep command will be used in conjunction with the movie Delay value. The amount of time to sleep will be used to calculate the number of frames to add to the movie to introduce the desired delay.

sleep 命令会与影片的 Delay（延迟）值配合使用：休眠时长会被换算成需要向影片添加的帧数，以引入所需的延迟。

Finally, there is a foreach option that allows the user loop over a list of parameter values. This can be used with any command that takes one or more arguments. For example it can be used with the pan to command to set way points when panning the image from one location to another. Or it could be used to incrementally zoom in/out. The syntax is

最后，还有一个 foreach 选项，允许用户遍历一组参数值。它可以用于任何带一个或多个参数的命令。例如，可以配合 pan to 命令，在把图像从一处平移到另一处时设置途经点；也可以用于逐级放大/缩小。语法为：

foreach {value1 value2 value3 ...} {command ... @ ...}

foreach 语法：第一对花括号内为要遍历的值列表，第二对花括号内为模板命令，其中 @ 会被依次替换为每个值。

The @ symbol in the command will be replaced with each of the specified values. Note: if a command takes multiple values, e.g. the coordinates required by the `pan to` command, then they must be enclosed in braces, {}.

命令中的 @ 符号会被依次替换为每个指定的值。注意：如果一条命令需要多个值（例如 pan to 命令所需的坐标），必须把它们用花括号 {} 包起来。

zoom to 2
zoom to 4
zoom to 1
foreach { \

     {165.3979999 -61.0543396} \
     {165.4389455 -61.0510670} \
     {165.4801702 -61.0521552} \
     {165.4951121 -61.0380736} \
     {165.5151265 -61.0274043} \
     {165.5052158 -61.0092326} \
     {165.4899765 -61.0009021} \
     {165.4583989 -60.9924361} \
     {165.4369801 -60.9902503} \
     {165.4124623 -60.9905203} \
     {165.3913201 -60.9943406} \

     {165.4008507 -61.0339772} \

该示例：先用 && 连续执行设置灰度颜色映射、平移、对数拉伸、设置拉伸限等命令（不每步加帧）；然后逐级缩放、画一个圆形区域，并用 foreach 在一组 fk5 天球坐标上依次平移，形成沿一个目标序列巡天的影片。
